# Short radio interjections and station surfing

The user approved the score and neural presenters, but requested much shorter
interjections and occasional music/noise/other-song/noise/news/noise/music
switches. All14 contextual scripts are now5–9 words, with encoded prepared
performances1.99–3.10 seconds long. Closures/weather still outrank banter, variants
avoid immediate repeats, and optional captions use exactly the selected text.
Examples: “Shortcut closed. Scenic route it is!”, “Wet pavement. Smooth moves,
folks!”, and “Traffic ahead. Never argue with a minivan!” These remain stock
synthetic presenters, not reviewed local accents or final dramatic performances.

## Sequence and limits

The first report is direct. Every other subsequent **station change** is eligible
for dial surfing; a repeated report on the same station never triggers extra song
snippets. If a prewarmed fragment is available, the sequence is:

1. Cut the old music and play180ms of tuning.
2. Play at most680ms from a different station's original score.
3. Play180ms tuning, then the short contextual report.
4. Play180ms tuning and start the selected full score.

The extra dial flourish adds at most1.22 seconds around the report. Its precise
rhythm is an authored listening hypothesis, not a research-derived attention
threshold. Missing/cold snippet files skip the flourish immediately. Snippet
loading never postpones a report. Two alternatives, each under a second, are
prewarmed alongside the normal bounded score/report cache. No extra full-length
song is decoded solely to create this effect.

The three680ms dial fragments are excerpts at29s of the already-approved original
mixes, generated by `tool/audio/surf_clips.py`. No third-party recordings or new
song generations are involved. Exact-text prepared reports were rebuilt with the
existing Kokoro v1.0 stock voices and local toolchain. Outdated unreferenced long
report files were removed. See [score provenance](../assets/audio/SCORE_NOTES.md)
and assets/audio/verification.json for source/model/file hashes and encoded-level
measurements. Existing full scores and MIDI remain unchanged.

## Browser behavior and sources

Buffered fragment duration uses the Web Audio audio clock; timers coordinate
station state rather than driving audio samples. [W3C Web Audio Recommendation,
AudioBufferSourceNode.start](https://www.w3.org/TR/webaudio/#dom-audiobuffersourcenode-start)
defines the scheduled start/offset/duration contract. The implementation also
follows the documented [AudioBufferSourceNode start parameters](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode/start).
These API references support implementation mechanics, not claims about optimal
radio pacing. The sequence remains an arcade listening experiment.

Pause, mute, hidden tabs, superseding reports and disposal invalidate the radio
epoch, stop active snippets/reports and clear the pending transition. A late
asset load cannot restart playback after disposal. Device speech is still the
fallback for missing prepared reports, without blocking simulation. Gameplay does
not wait for any radio/audio operation and no TTS service is contacted during play.
